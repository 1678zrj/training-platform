### 问题一：学生退出实验时，停止容器还是删除容器？

这取决于你的**资源（GPU/内存）紧张程度**和**数据持久化策略**。对于 A800 这种昂贵的 GPU 资源，推荐采用 **“分级释放策略”**。

#### 1. 核心矛盾

* **停止 (Stop)**：释放 CPU/GPU 和内存，但**占用磁盘空间**（容器层未删除）和 **IP/端口资源**。下次启动极快（因为容器还在）。
* **删除 (Remove)**：释放所有资源。下次进入需要重新 `docker run`，速度稍慢，且如果没挂载数据卷，数据会丢失。

#### 2. 结合你的数据库表设计的建议方案

你的 `user_labs` 表有 `status` 字段，`images` 表有 `work_dir`，这很好。

**推荐策略：挂载持久化 + 激进删除**

由于你是实训平台，学生的数据必须持久化（哪怕容器删了，代码不能丢）。

1. **启动时 (Docker Run)**：
* 必须使用 `-v` 挂载目录。将宿主机的 `/data/students/{user_id}/{exp_id}` 挂载到容器的 `work_dir`。
* **结论**：只要挂载了，容器本身就是“抛弃型”的壳子，随时可以删。


2. **退出动作**：
* **临时离开（关闭网页）**：前端检测 WebSocket 断开或心跳超时 -> 后端触发 `docker stop`。
* 状态：`user_labs.status = "stopped"`
* 资源：释放显存给其他人用。


* **结束实验（点击“结束”按钮）**：后端触发 `docker rm`。
* 状态：`user_labs.status = "unstarted"`
* 资源：释放所有资源。




3. **定期清理（定时任务）**：
* 对于 `stopped` 状态超过 24 小时的容器 -> 执行 `docker rm`。
* **理由**：防止僵尸容器占满磁盘。

### 问题二：Nginx 单端口复用（仿 JupyterHub）可行性分析

你给出的 Nginx 配置思路是**正确**的，利用 Nginx 的 `proxy_pass` 配合变量来实现动态代理。

**但是！有一个巨大的“坑”需要解决：Base URL（基础路径）。**

#### 1. 那个“坑”是什么？

如果你的 Nginx 配置是访问 `http://lab.com/env/10001/`，然后代理到内部的 `127.0.0.1:10001`。
当 Jupyter 容器接收到请求时，它默认认为自己运行在根路径 `/`。

* Jupyter 返回的 HTML 会引用 `/static/main.js`。
* 浏览器会请求 `http://lab.com/static/main.js`。
* **错误**：Nginx 此时不知道这个请求属于 10001 端口，于是报 404。

#### 2. 如何解决？（必须配合 Docker 启动命令）

Jupyter（以及 VSCode Server）都支持配置 **Base URL**。
你必须在 Python 后端启动 Docker 时，动态注入这个参数。

**修改后的 Docker 启动命令逻辑（Backend Service 层）：**

```python
# 假设分配的宿主机端口是 host_port (例如 10001)
base_url = f"/env/{host_port}" 

cmd = [
    "jupyter", "lab",
    f"--ServerApp.base_url={base_url}",  # 关键！告诉 Jupyter 它被挂载在子路径下
    "--ServerApp.allow_origin='*'",
    "--ip=0.0.0.0",
    "--port=8888", # 容器内部依然是 8888
    # ... 其他参数
]

```

#### 3. 修正后的 Nginx 配置（更安全、更健壮）

你的正则配置虽然可行，但直接把 `target_port` 暴露给用户有安全风险（用户可能扫你的 22 端口或 6379 端口）。建议加一层校验。

```nginx
http {
    map $http_upgrade $connection_upgrade {
        default upgrade;
        ''      close;
    }

    server {
        listen 80;
        server_name your-lab.com;

        # 前端页面
        location / {
            root /usr/share/nginx/html;
            try_files $uri $uri/ /index.html;
        }

        # 后端 API
        location /api/ {
            proxy_pass http://backend:8000;
        }

        # --- 核心：动态代理到 Jupyter ---
        # 约定：只允许代理 10000 到 20000 之间的端口，防止用户访问系统端口
        location ~ ^/env/(?<target_port>1\d{4})(/.*)?$ {
            # 1. 代理地址
            proxy_pass http://host.docker.internal:$target_port; 
            # 注意：如果你 Nginx 也在容器里，访问宿主机端口需要用 host.docker.internal 
            # 如果 Nginx 直接装在宿主机，用 http://127.0.0.1:$target_port

            # 2. WebSocket 支持 (必须)
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection $connection_upgrade;
            
            # 3. 关键 Header，欺骗 Jupyter 让它以为自己在根目录或正确处理 HTTPS
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Scheme $scheme;
            
            # 4. 超时设置
            proxy_read_timeout 86400;
            proxy_send_timeout 86400;
        }
    }
}

```

### 结合你的数据库表 (`containers`) 的最终流程

现在我们把数据库、后端逻辑和 Nginx 串起来：

1. **用户点击“开始实训”**：
* 前端调 API `/api/v1/labs/start`。


2. **后端 (Service 层)**：
* **分配端口**：找一个未使用的端口（比如 10001）。
* **记录数据库**：在 `containers` 表插入一条记录：
* `container_id`: (Docker ID)
* `host_port`: **10001**
* `url_token`: (随机生成，例如 `abcd-1234`) —— *其实既然用了 Nginx 正则匹配端口，这个 token 可以暂时只做鉴权用，或者简化直接用端口号做路径。*


* **启动 Docker**：
```bash
docker run -d -p 10001:8888 \
-v /data/students/1/10:/workspace \
my-jupyter-image \
jupyter lab --ServerApp.base_url=/env/10001

```




3. **前端跳转**：
* 后端返回 URL：`http://your-lab.com/env/10001/?token=jupyter_token`
* 前端 `window.open` 打开这个链接。


4. **访问流程**：
* 浏览器请求 `/env/10001/`。
* Nginx 正则匹配到 `target_port = 10001`。
* Nginx 转发给 `127.0.0.1:10001`。
* 容器内的 Jupyter 收到请求，一看 Base URL 是 `/env/10001`，匹配成功，返回页面。
* 页面里的 JS 请求 `/env/10001/static/style.css`。
* Nginx 再次匹配，转发成功。



### 总结

1. **关于退出**：推荐 **“人走停止，完结删除”** 的策略。必须使用 `-v` 挂载宿主机目录保证数据不丢。
2. **关于 Nginx**：你的方案**完全可行**，是标准的轻量级 JupyterHub 实现方式。
3. **关键点**：**Docker 启动命令必须加上 `--base_url` 参数**，且该参数必须与 Nginx 的 `location` 路径完全一致。
