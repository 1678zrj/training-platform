这是一个非常关键的工程问题。在 Docker 架构中，**文件权限（Permissions）**和**挂载策略（Mounting Strategy）**往往比写代码更折磨人。如果设计不好，会出现“学生无法保存代码”、“误删公共数据集”或者“提交作业时后端读不到文件”等情况。

基于你的 **FastAPI + SQLite + Docker** 架构，我为你设计了一套**标准化的目录结构**和**权限管理方案**。

---

### 1. 宿主机（服务器）目录结构设计

建议在服务器上开辟一个独立的数据分区（如 `/data`），并建立统一的根目录 `ai_platform`。

```text
/data/ai_platform/
├── database/                # 存放 SQLite 数据库文件
│   └── app.db
├── resources/               # 【公共资源区】管理员上传，只读
│   ├── templates/           # 实验代码模板 (如 exp1_resnet)
│   ├── datasets/            # 大型数据集 (如 coco, imagenet)
│   └── docs/                # 实验指导书 markdown
├── workspaces/              # 【学生工作区】动态生成，Docker 挂载点
│   ├── user_101/            # 用户 ID 分组
│   │   ├── exp_1/           # 实验 ID 分组 (挂载到容器 /workspace)
│   │   └── exp_2/
│   └── user_102/
└── submissions/             # 【作业归档区】FastAPI 写入，只读
    ├── exp_1/
    │   └── 101_submission.zip
    └── exp_2/

```

### 2. 三大核心读写策略

#### A. 实验模板：复制策略 (Copy-on-Write)

**场景**：实验1有一个初始代码 `main.py`。
**问题**：不能直接把 `resources/templates/exp1` 挂载给学生，否则一个学生改了，所有学生拿到的模板都变了。
**解决方案**：
当学生点击“开始实验”且 `status` 为 `unstarted` 时，FastAPI 执行：

1. 读取 `Experiment` 表里的 `template_path` (例如 `/data/ai_platform/resources/templates/exp1`)。
2. 在 `workspaces` 下创建学生目录 `/data/ai_platform/workspaces/user_{id}/exp_{id}`。
3. 使用 `shutil.copytree` 把模板里的文件**复制**过去。
4. 启动 Docker，将**复制后的目录**挂载到容器内。

#### B. 数据集：只读挂载策略 (Read-Only Mount)

**场景**：ImageNet 数据集有 100GB，不能给每个学生都复制一份。
**解决方案**：
直接将宿主机的 `datasets` 目录挂载进容器，但加上 `:ro` (Read Only) 参数。

* **宿主机路径**：`/data/ai_platform/resources/datasets/imagenet`
* **容器内路径**：`/data/imagenet`
* **Docker 参数**：`-v /host/path:/container/path:ro`

这样学生能读取数据训练，但无法删除或修改源文件。

#### C. 作业提交：隔离存储策略

**场景**：学生提交作业。
**解决方案**：
不要把作业存在学生的 `workspaces` 里（因为学生可能会删容器、删文件）。
FastAPI 接收上传流，直接写入 `/submissions/exp_{id}/`。这个目录**不挂载**进容器，只有 FastAPI (后端) 有权限读写，保证了作业的不可篡改性。

### 3. 最头疼的权限问题 (Permission) 怎么解？

在 Docker 中，最常见的问题是：**容器里是 root (或 Jovyan)，宿主机是普通用户，导致文件写不进去，或者写出来的文件宿主机删不掉。**

推荐采用 **"UID 1000 统一策略"**。

#### 背景知识

* 大多数科学计算镜像（如 Jupyter/Scipy）默认用户是 `jovyan`，UID 通常是 **1000**。
* 如果容器里的 UID 是 1000，它去写挂载的目录，宿主机上该文件的拥有者 UID 也会变成 1000。

#### 实施步骤

**第一步：设置宿主机目录权限**
你的 FastAPI 程序如果是用 `root` 跑的，那没问题。如果是用普通用户跑的，请确保该用户能读写 `/data/ai_platform`。

更重要的是，你需要让**学生的工作区**对 UID 1000 开放权限。在 FastAPI 创建目录的代码中加入：

```python
import os
import shutil

def init_student_workspace(src_template, target_dir):
    # 1. 复制模板
    shutil.copytree(src_template, target_dir)
    
    # 2. 【关键】修改权限
    # 递归修改文件夹所有者为 UID 1000 (Jupyter默认用户)
    # 这样容器内的用户才有权限在这个目录下写代码、保存模型
    os.system(f"chown -R 1000:1000 {target_dir}")

```

**第二步：Docker 启动命令设计**
在 Python 调用 Docker SDK 时，严格控制挂载参数。

```python
# 假设使用 docker-py
container = client.containers.run(
    image="lab/pytorch:1.13",
    detach=True,
    # 端口映射
    ports={'8888/tcp': available_port},
    # 挂载卷配置
    volumes={
        # 1. 学生工作区 (读写)
        f'/media/ai_platform/workspaces/user_{uid}/exp_{eid}': {
            'bind': '/workspace',  # 容器内的工作目录
            'mode': 'rw'           # 读写模式
        },
        # 2. 公共数据集 (只读)
        f'/media/ai_platform/resources/datasets': {
            'bind': '/media/datasets',
            'mode': 'ro'           # 【关键】只读模式
        }
    },
    # 环境变量 (Jupyter 不要是 root 运行，防止安全风险)
    environment=[
        "NB_UID=1000",
        "NB_GID=1000",
        "CHOWN_HOME=yes" #有些镜像支持启动时自动修正权限
    ]
)

```

### 4. 总结：文件流转全景图

1. **管理员** 通过 FTP/SSH 把 Markdown 和 初始代码 传到 `resources`。
2. **学生** 点击开始 -> **FastAPI** 将代码从 `resources` **复制** 到 `workspaces/u_xx` -> **Docker** 启动并挂载该目录。
3. **学生** 在 Jupyter 中写代码 -> 数据实时保存在宿主机的 `workspaces/u_xx` (容器挂了数据也在)。
4. **学生** 训练模型读取数据 -> Docker **只读读取** `resources/datasets`。
5. **学生** 提交作业 -> **FastAPI** 读取 `workspaces` 里的文件打包，或者接收上传，转存到 `submissions` 归档。

### 5. 补充建议

* **`.dockerignore` 机制**：在学生提交作业打包时，让 FastAPI 自动忽略 `__pycache__`、`.ipynb_checkpoints` 以及超大的 `.pth` 模型文件（除非作业要求提交模型），否则服务器硬盘很快就会炸。
* **定期清理**：写一个定时脚本（Cronjob），每周清理一次 `workspaces` 里超过 30 天未变动且容器已销毁的临时文件（可结合数据库 `last_accessed` 字段判断）。

这一套设计能最大程度保证：**数据不丢失、环境不冲突、作业能留底**。你觉得这个目录结构在你的 A800 服务器上容易落地吗？
