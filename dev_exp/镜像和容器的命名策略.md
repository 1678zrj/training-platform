这是一个非常敏锐且关键的调整！做 AI 实训平台，**资源隔离**和**命名规范**是系统稳定运行的核心。如果不加限制，一个学生写个死循环或者申请超大显存，整个实验室服务器都会崩掉。

我们来逐一解决你的疑虑，并更新设计。

---

### 一、 Docker 能控制 CPU 最小值和最大值吗？

Docker 的资源控制非常强大，但它的逻辑和虚拟机（VM）略有不同：

1. **最大值 (Hard Limit) - **✅ **完全支持**
* **内存**：可以直接限制，例如 `4G`。超过就 OOM Kill（被杀掉）。
* **CPU**：可以直接限制核数。例如 `cpus=2.0` 表示该容器最多只能用满 2 个核的时间片（不管你有多少个物理核）。


2. **最小值 (Soft Limit / Reservation) - **⚠️ **相对支持**
* **内存**：有 `--memory-reservation`，但它只是一个“软限制”，只有当宿主机内存紧张时才会触发回收。
* **CPU**：Docker 没有绝对的“独占锁死 1 个核给某人”的概念（除非绑定具体核 `cpuset`，但这管理很复杂）。它使用的是 **CPU 权重 (`cpu_shares`)**。
* *举例*：默认权重是 1024。如果你给容器 A 权重 1024，容器 B 权重 512。当 CPU 忙不过来时，A 获得的 CPU 时间是 B 的两倍。


* **结论**：对于实训平台，**限制“最大值”**（防止学生把服务器跑死）比“最小值”更重要。通常我们只设置 `nano_cpus` (上限) 和 `mem_limit` (上限)。


3. **GPU 控制 - **✅ **完全支持**
* 需要安装 NVIDIA Container Toolkit。
* 可以指定使用哪几张卡（如 `device=0,1`），或者只指定数量（如 `count=1`）。

### 二、 镜像名与容器名的统一前缀

**这是必须的。**

1. **镜像名 (Image Name)**
* **建议前缀**：`lab-images/` 或 `course-ai/`。
* **理由**：将来你可能搭建私有仓库（Harbor），规范的命名方便管理。
* **示例**：`lab-images/pytorch:1.13-cuda11.7`, `lab-images/tensorflow:2.10`.


2. **容器名 (Container Name)**
* **建议格式**：`lab_{user_id}_{exp_id}_{random_suffix}`
* **理由**：
* **防冲突**：同个用户可能同时开两个实验，或者不同用户开同一个实验。
* **易运维**：你在服务器上输 `docker ps` 时，一眼就能看出是哪个学生的哪个实验在跑。
* **代码清理**：后端重启时，可以扫描所有以 `lab_` 开头的容器并将其停止，防止僵尸进程。

### 三、 修改数据库设计 (`backend/app/models/lab.py`)

我们需要修改 **`Experiment`** 表（或者 `Image` 表）。

**策略建议**：
建议将资源限制放在 **`Experiment` (实验)** 表中。

* *理由*：同一个 `PyTorch` 镜像，做“线性回归实验”可能只需要 1核 2G，但做“Transformer 训练”可能需要 4核 16G + GPU。**实验内容决定了资源需求。**

### 四、 修改 Docker 启动逻辑 (`backend/app/services/docker_service.py`)

现在，我们需要在启动容器时应用这些参数。这部分代码展示了如何使用 Python Docker SDK 映射这些字段。

**新建或修改 `backend/app/services/docker_service.py`：**

```python
import docker
from docker.types import DeviceRequest
from app.models.lab import Experiment, User
from fastapi import HTTPException

# 初始化 Docker 客户端
client = docker.from_env()

# 定义统一前缀
CONTAINER_PREFIX = "lab_student" 

class DockerService:
    @staticmethod
    def run_experiment_container(
        user: User, 
        experiment: Experiment, 
        image_tag: str
    ) -> dict:
        """
        启动实验容器，应用资源限制
        """
        # 1. 生成规范的容器名: lab_student_{uid}_{exp_id}
        # 加个随机码防止极低概率的冲突也可以，但这里为了演示简便先去掉
        container_name = f"{CONTAINER_PREFIX}_{user.id}_{experiment.id}"

        # 2. 检查是否已存在 (防止重复启动)
        try:
            existing = client.containers.get(container_name)
            if existing.status == "running":
                return {"container_id": existing.id, "status": "exists"}
            else:
                existing.remove() # 如果是停止状态，删掉重开
        except docker.errors.NotFound:
            pass

        # 3. 准备 GPU 配置
        device_requests = []
        if experiment.use_gpu and experiment.gpu_count > 0:
            # 申请指定数量的 Nvidia GPU
            device_requests.append(
                DeviceRequest(count=experiment.gpu_count, capabilities=[['gpu']])
            )

        # 4. 启动容器 (核心参数配置)
        try:
            container = client.containers.run(
                image=image_tag,
                name=container_name,
                detach=True,
                
                # --- 资源限制映射 ---
                # nano_cpus 接受整数，1核 = 10^9。如 2.5 核 = 2500000000
                nano_cpus=int(experiment.cpu_limit * 1_000_000_000),
                
                # 内存直接传字符串 "2g"
                mem_limit=experiment.mem_limit,
                
                # GPU 配置
                device_requests=device_requests,

                # 网络配置 (如果不通过 Nginx 转发，可能需要映射端口)
                publish_all_ports=True, 
                
                # 挂载工作目录 (把宿主机的 data 目录挂进去，持久化保存学生作业)
                volumes={
                    f"/home/yourproject/data/workspace/{user.id}": {
                        'bind': '/workspace', 'mode': 'rw'
                    }
                },
                
                # 环境变量 (可选，传给 Jupyter)
                environment={
                    "JUPYTER_TOKEN": "lab-token" # 简化处理，实际应随机生成
                }
            )
            
            # 获取映射出的端口 (比如 8888 映射到了宿主机 32768)
            container.reload() # 刷新属性
            host_port = container.ports['8888/tcp'][0]['HostPort']

            return {
                "container_id": container.id,
                "container_name": container.name,
                "host_port": host_port,
                "status": "started"
            }

        except Exception as e:
            print(f"启动容器失败: {str(e)}")
            raise HTTPException(status_code=500, detail=f"容器启动失败: {str(e)}")

```

### 总结变更点

1. **数据库**：`Experiment` 表增加了 `cpu_limit`, `mem_limit`, `use_gpu`, `gpu_count`。
2. **规范**：
* **容器名前缀**：`lab_student_`，方便管理。
* **最大值优先**：通过 `nano_cpus` 和 `mem_limit` 严格防止资源超卖。


3. **代码**：Docker Service 中加入了 `device_requests` 处理 GPU，以及体积换算的 CPU 限制。

这样设计后，你在后台添加一个“PyTorch大模型微调”实验时，可以设置 **8核 16G 1张GPU**；而添加一个“Python基础”实验时，设置 **0.5核 128M 无GPU**。这就非常合理了！
